# Repact — логика гайда для новых тестировщиков

Статус: продуктовая и техническая спецификация перед реализацией.  
Версия сценария: `1`.

## 1. Зачем нужен гайд

Новый человек за 60–90 секунд должен понять:

1. Repact — это челленджи, где камера считает и подтверждает повторения.
2. Можно вступить в готовый челлендж, создать свой или принять приглашение друга.
3. Камеру нужно поставить так, чтобы тело полностью попадало в кадр; приложение само подскажет, если человека не видно.
4. После тренировки можно закрыть дневную цель, посмотреть прогресс и поделиться результатом.
5. Во время тестирования можно быстро отправить отчёт о проблеме.

Главный результат гайда — не просто просмотр всех экранов, а первое полезное действие: тест камеры или переход к конкретному челленджу.

## 2. Где гайд находится в общем пути

```text
Новый пользователь
  → текущий онбординг (имя, параметры, упражнения, цель, аккаунт)
  → мини-гайд Repact (4 экрана)
  → тест камеры
  → выбранное действие
      ├─ приглашён другом → приглашённый челлендж
      ├─ хочет вступить → список челленджей
      └─ хочет создать → создание челленджа
  → Home с чек-листом тестировщика
```

Гайд не заменяет текущий онбординг. Текущий онбординг настраивает профиль и дневную норму, новый гайд объясняет продукт и приводит к первому действию.

## 3. Когда показывать гайд

### Автоматически

Показывать один раз сразу после завершения текущего онбординга, если у пользователя ещё нет сохранённого решения по гайду версии `1`.

### Не показывать автоматически

- Пользователям, которые уже завершили или пропустили гайд.
- При каждом открытии приложения.
- Поверх активной тренировки, камеры, системного окна шеринга или другой полноэкранной формы.
- Старым пользователям после релиза: для них гайд доступен вручную из профиля, но не появляется внезапно.

### Повторное открытие

В Profile добавить пункт `Як працює Repact` / `Как работает Repact` / `How Repact works`.

Повторный просмотр:

- начинается с первого экрана;
- не сбрасывает выполненный чек-лист;
- не меняет уже выбранный маршрут;
- после закрытия возвращает в Profile.

## 4. Четыре экрана

### Экран 1 — что такое Repact

Цель: за одну фразу объяснить идею продукта.

- Заголовок: `Тренування, які потрібно довести`
- Смысл: камера считает повторения и подтверждает результат.
- Коротко показать цепочку: `Постав телефон → Виконай вправу → Отримай підтверджений результат`.
- Слоган: `Не просто кажи. Доведи це! — Repact`
- Основная кнопка: `Далі`
- Вторичная кнопка: `Пропустити`

Никаких продуктовых действий на этом экране.

### Экран 2 — как работает камера

Цель: снять тревогу перед первой тренировкой.

- Поставить телефон устойчиво.
- Полностью попасть в кадр.
- Начать упражнение.
- Если тело не видно, приложение показывает подсказку.
- Звуковые сигналы можно включать и выключать.
- Поддерживаемые упражнения: отжимания, приседания, подтягивания, брусья.
- Важно: обработка камеры происходит на устройстве; видео не отправляется автоматически.
- Основная кнопка: `Зрозуміло`
- Вторичная кнопка: `Пропустити`

Кнопка не открывает разрешение камеры. Разрешение запрашивается только после явного нажатия `Протестувати камеру` на последнем экране.

### Экран 3 — выбрать свой путь

Цель: связать объяснение с намерением пользователя.

Три варианта:

1. `Приєднатися до челенджу`
2. `Створити свій челендж`
3. `Прийняти запрошення друга`

Выбор сохраняется как `startIntent`.

Правила:

- Без приглашения по умолчанию выбран вариант `join`.
- Если пользователь открыл ссылку `?join=<id>`, автоматически выбран вариант `invite`.
- Для приглашения вместо общего текста желательно показать название найденного челленджа.
- Вариант `invite` без сохранённой ссылки объясняет функцию, но ведёт в список челленджей.
- Основная кнопка: `Далі`
- Вторичная кнопка: `Пропустити`

### Экран 4 — чек-лист тестирования

Цель: показать, что именно можно проверить в приложении.

Список:

1. Протестировать камеру.
2. Вступить в челлендж или создать свой.
3. Пригласить друга.
4. Выполнить тренировку.
5. Закрыть дневную цель.
6. Поделиться результатом.
7. Посмотреть прогресс.

Отчёт об ошибке показывается отдельной подсказкой, а не обязательным пунктом.

Кнопки:

- Основная: `Протестувати камеру`
- Вторичная без приглашения: `Перейти в застосунок`
- Вторичная с приглашением: `Переглянути запрошення`
- Ссылка: `Повідомити про проблему`

После открытия этого экрана гайд ещё не считается завершённым. Он завершается нажатием основной/вторичной кнопки или явным `Пропустити`.

## 5. Маршрутизация после гайда

### После теста камеры

Успешный тест камеры отмечает только `cameraTested`. Он не добавляет повторения в челлендж, не закрывает день и не начисляет награду.

После экрана `Camera check complete`:

| Сохранённый маршрут | Следующий экран |
|---|---|
| `invite` и приглашение найдено | Детали приглашённого челленджа; если пользователь не участник — форма вступления |
| `invite`, но приглашение не найдено | Список челленджей + понятное сообщение, что приглашение пока не загрузилось |
| `join` | Вкладка Challenges |
| `create` | Мастер создания челленджа |

### Если пользователь не тестирует камеру

Кнопка `Перейти в застосунок` сразу выполняет тот же маршрут. Камеру можно проверить позже из чек-листа.

### Авторизация

Если выбранное действие требует аккаунта:

1. сохранить точное отложенное действие;
2. открыть существующий экран авторизации;
3. после успешного входа продолжить это действие;
4. не отправлять пользователя на Home между авторизацией и продолжением.

Отложенное действие должно содержать `kind` и, для приглашения, `challengeId`.

## 6. Ссылка-приглашение

Текущего значения из URL недостаточно: оно теряется после очистки URL или перезагрузки. До очистки `?join=<id>` нужно сохранить приглашение.

Рекомендуемое состояние:

```js
pendingInvite = {
  challengeId: "main",
  receivedAt: 1784800000000
}
```

Правила жизни приглашения:

- сохраняется сразу при чтении URL;
- переживает гайд, тест камеры, авторизацию, перезагрузку и временный офлайн;
- очищается после успешного вступления или явного отказа пользователя;
- новое приглашение заменяет старое;
- не должно повторно открывать форму вступления, если пользователь уже участник;
- если челлендж ещё не получен из Firebase, показать загрузку и повторить проверку после синхронизации;
- если челлендж удалён или недоступен, показать ошибку и кнопку перейти к другим челленджам.

## 7. Состояние гайда

Хранить одним объектом, а не набором несвязанных флагов:

```js
testerGuide = {
  version: 1,
  status: "not_started", // not_started | in_progress | completed | skipped
  step: 0,               // 0...3
  startIntent: "join",   // join | create | invite
  updatedAt: 1784800000000
}
```

Поведение:

- `not_started` → открыть экран 1;
- при первом переходе вперёд → `in_progress`;
- после закрытия приложения на середине → продолжить с сохранённого шага;
- `completed` и `skipped` одинаково запрещают повторный автоматический показ;
- ручной просмотр из Profile не меняет статус и шаг основного прохождения;
- поле `version` позволяет в будущем показать принципиально новый гайд, но повышение версии само по себе не должно принудительно показывать его старым пользователям без отдельного решения.

## 8. Чек-лист после гайда

После гайда чек-лист показывается компактной карточкой на Home, пока пользователь не:

- выполнит все пункты; или
- скроет карточку вручную.

Повторно открыть чек-лист можно через `Як працює Repact` в Profile.

### Как пункты отмечаются

| Пункт | Источник истины |
|---|---|
| Тест камеры | успешное завершение демо или хотя бы одна настоящая тренировка с распознанными повторениями |
| Вступить/создать | есть челлендж, где пользователь участник, созданный или присоединённый после начала тестового гайда |
| Пригласить друга | системный share завершился успешно или ссылка была успешно скопирована |
| Выполнить тренировку | в сохранённой сессии есть хотя бы одно распознанное повторение |
| Закрыть день | дневная цель впервые стала выполненной |
| Поделиться | успешный системный share или успешное сохранение файла результата |
| Посмотреть прогресс | пользователь открыл вкладку Progress после прохождения гайда |

Не считать отменённый системный share выполненным действием.

Данные, которые уже можно вывести из `app`, не дублировать. Отдельно сохранять только события, которые нельзя надёжно восстановить: тест демо-камеры, успешный invite share, открытие Progress, успешный share результата и скрытие карточки.

Рекомендуемая форма:

```js
testerProgress = {
  startedAt: 1784800000000,
  cameraTested: false,
  inviteShared: false,
  resultShared: false,
  progressViewed: false,
  dismissed: false
}
```

## 9. Приоритеты экранов при запуске

Чтобы полноэкранные состояния не конфликтовали, использовать один порядок:

1. Активная тренировка/камера.
2. Продолжение обязательной авторизации.
3. Незавершённый основной онбординг.
4. Незавершённый гайд нового пользователя.
5. Сохранённое приглашение.
6. Обычная вкладка приложения.

Гайд не должен открываться поверх уже начатой тренировки или формы.

## 10. Закрытие, Back и Skip

- Системный Back на экранах 2–4 возвращает на предыдущий экран гайда.
- Back на первом экране во время автоматического показа работает как `Пропустити`, но перед выходом нужна короткая подтверждающая форма.
- `Пропустити` сразу сохраняет `status: skipped` и выполняет выбранный маршрут.
- При ручном просмотре из Profile кнопка закрытия просто возвращает в Profile.
- Закрытие браузера без Skip не меняет статус на `skipped`; следующий запуск продолжает гайд.

## 11. Ошибки и сложные случаи

- Камера запрещена: не отмечать пункт; показать, как дать доступ, и оставить `Спробувати ще раз` + `Пізніше`.
- Камера недоступна: разрешить продолжить в приложение.
- Человек не помещается в кадр: использовать уже существующие подсказки камеры, а не создавать отдельную систему.
- Офлайн: четыре информационных экрана работают; приглашение сохраняется; сетевое действие ждёт подключения.
- Пользователь уже состоит в приглашённом челлендже: открыть его детали без формы вступления.
- Пользователь выбрал `create`, затем пришло новое приглашение: новое приглашение имеет приоритет только после явного открытия ссылки.
- Смена языка внутри гайда обновляет весь текст без сброса шага.
- Сброс тестовых данных должен также очищать состояние гайда, чек-листа и отложенного приглашения.

## 12. Аналитика

События без персональных данных:

- `tester_guide_started` — источник `organic | invite | profile`;
- `tester_guide_step_viewed` — `step`;
- `tester_guide_path_selected` — `join | create | invite`;
- `tester_guide_skipped` — `step`, `source`;
- `tester_guide_completed` — `path`, `camera_first`;
- `camera_demo_started`;
- `camera_demo_completed` — число распознанных повторений;
- `tester_checklist_item_completed` — `item`;
- `tester_checklist_dismissed`;
- `tester_guide_reopened`.

Каждый пункт чек-листа отправляет событие только один раз.

## 13. Тексты и языки

Все строки должны идти через существующую функцию переводов.

Обязательная украинская формулировка слогана:

`Не просто кажи. Доведи це! — Repact`

Английская:

`DON’T JUST SAY IT. PROVE IT. — REPACT`

Русскую версию можно оставить:

`Не просто говори. Докажи это! — Repact`

Названия упражнений и подсказки камеры должны использовать существующие переводы, чтобы гайд и тренировка не называли одно действие по-разному.

## 14. Точки реализации

- `app.js`
  - состояние гайда и чек-листа;
  - чтение и хранение приглашения;
  - четыре рендера и обработчики;
  - единая функция завершения/продолжения маршрута;
  - отметки событий чек-листа в существующих успешных действиях;
  - пункт в Profile и карточка на Home.
- `styles.css`
  - полноэкранный гайд, карточки выбора, прогресс `1/4`, адаптация под safe area.
- `ua.js` и словарь RU/EN в `app.js`
  - все новые строки.
- `tests/tester-guide.spec.js`
  - отдельные end-to-end сценарии.
- `sw.js` и версия ассетов
  - обновить кэш только после готовой реализации.

Не создавать вторую камеру, второй мастер челленджей или отдельную копию логики шеринга. Гайд должен вызывать уже существующие функции.

## 15. Проверка перед публикацией

Реализация считается готовой, если проходят эти сценарии:

1. Новый пользователь без ссылки завершает онбординг и видит экран `1/4`.
2. После перезагрузки на экране `3/4` гайд продолжается с `3/4`.
3. Skip больше не показывает гайд автоматически.
4. Завершённый гайд больше не показывается автоматически.
5. Старый пользователь не получает новый гайд внезапно.
6. Гайд повторно открывается из Profile и возвращается обратно в Profile.
7. Пользователь по `?join=main` проходит онбординг, гайд, демо и попадает в `main`.
8. То же приглашение переживает перезагрузку и авторизацию.
9. Уже вступивший пользователь не видит повторную форму вступления.
10. Отказ камеры не отмечает пункт чек-листа и не блокирует приложение.
11. Демо не меняет баланс, повторения, день и прогресс челленджа.
12. Успешное реальное действие отмечает соответствующий пункт чек-листа.
13. Отмена системного share ничего не отмечает.
14. Украинский, английский и русский тексты переключаются без потери шага.
15. На маленьком iPhone и устройстве с Dynamic Island кнопки не попадают под safe area.
16. Существующие тесты онбординга, приглашений, камеры, создания и шеринга остаются зелёными.

## 16. Что сознательно не входит в первую версию

- Обязательное прохождение всех функций до входа в приложение.
- Награда или монеты за просмотр гайда.
- Отдельное серверное хранение чек-листа.
- Новые упражнения.
- Видео-инструкция внутри гайда.
- Автоматический запрос доступа к камере без нажатия пользователя.
- Принудительный повтор гайда после каждого обновления.
